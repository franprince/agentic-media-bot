# Project Rules

- **THE BOT RUNS LOCALLY NOW**: `src/bot.ts` (as `agentic-media-bot.service`) is the one and only production instance, running on this machine. The old remote Coolify deployment is retired — do not treat a push to `master` as implying a bot is running elsewhere. Never run a *second* local copy of the bot (e.g. `bun run src/bot.ts` in a dev shell while the systemd service is also up) — that causes Telegram 409 conflicts with itself. Check `systemctl --user status agentic-media-bot` first. For the same reason, never call Telegram's `getUpdates` as a probe — it conflicts with the running instance's long polling.
- **THE PROXY IS RETIRED, NOT DELETED**: `agentic-media-proxy.service` is stopped and disabled. `proxy.ts` and `USE_PROXY`/`PROXY_URL`/`PROXY_SECRET_KEY` still exist in case a remote-brain setup is needed again later, but nothing currently depends on them — the bot talks to Radarr/Sonarr/Plex/qBittorrent/NZBGet directly over `localhost`. Don't "fix" the proxy path unless the user is explicitly bringing that architecture back.
- **READ `DEPLOYMENT.md` BEFORE DEBUGGING DELIVERY**: It documents the current single-host topology, the retired remote/proxy path, and per-hop verification commands.
